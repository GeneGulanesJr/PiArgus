# Plan: Single Docker Container for PiArgus

## Goal
Replace smolvm with a **single Docker container** running Obscura + Chromium/Puppeteer + SearXNG + DuckDuckGo scraping. Works on Windows, Mac, Linux.

---

## Why a Single Container?

- One `docker run` to start everything — zero configuration
- `supervisord` manages all internal processes
- Smaller total footprint than 3 separate containers (~700MB vs ~1.5GB)
- Simplified networking — SearXNG reachable at `localhost:8888`, no inter-container DNS

## Why Debian (not Alpine)?

Obscura's Linux binary requires glibc 2.35+ (targets Ubuntu 22.04). Alpine uses musl libc — incompatible. Debian bookworm-slim is the smallest glibc-based image with Node.js.

---

## Container Architecture

```
┌─────────────────── piargus (single container) ───────────────────┐
│                                                                   │
│  supervisord (PID 1)                                             │
│  ├── obscura serve --port 9222     (light tier: fetch/scrape)    │
│  └── granian searxng.webapp --port 8080  (SearXNG metasearch)    │
│                                                                   │
│  Chromium (on-demand via docker exec + puppeteer-core)           │
│  └── heavy tier: screenshots, clicks, form fills                 │
│                                                                   │
│  Ports: 9222 (Obscura CDP), 8080 (SearXNG)                      │
│  Host mapping: 9222→9222, 8888→8080                              │
└───────────────────────────────────────────────────────────────────┘
```

| Service | Runs as | Purpose | Port |
|---------|---------|---------|------|
| Obscura | supervisord background process | Light tier fetch/scrape/eval + DDG HTML scraping | 9222 |
| Chromium | on-demand via `docker exec node ...` | Heavy tier screenshots/interactions (puppeteer-core) | — |
| SearXNG | supervisord background process (Granian ASGI) | Metasearch engine (JSON API) | 8080 (host: 8888) |

### 1. `Dockerfile`

```dockerfile
FROM node:20-slim

# ── System dependencies ──────────────────────────────────────
RUN apt-get update && apt-get install -y --no-install-recommends \
    chromium \
    python3 \
    python3-pip \
    python3-venv \
    supervisor \
    curl \
    ca-certificates \
    fonts-liberation \
    libappindicator3-1 \
    libasound2 \
    libatk-bridge2.0-0 \
    libatk1.0-0 \
    libcups2 \
    libdbus-1-3 \
    libgdk-pixbuf2.0-0 \
    libnspr4 \
    libnss3 \
    libx11-xcb1 \
    libxcomposite1 \
    libxdamage1 \
    libxrandr2 \
    xdg-utils \
    && rm -rf /var/lib/apt/lists/*

# ── Puppeteer-core (global) ──────────────────────────────────
RUN npm install -g puppeteer-core

# ── Obscura binary ───────────────────────────────────────────
RUN curl -LO https://github.com/h4ckf0r0day/obscura/releases/latest/download/obscura-x86_64-linux.tar.gz \
    && tar xzf obscura-x86_64-linux.tar.gz -C /usr/local/bin/ \
    && rm obscura-x86_64-linux.tar.gz \
    && chmod +x /usr/local/bin/obscura

# ── SearXNG + Granian ────────────────────────────────────────
RUN pip3 install --no-cache-dir --break-system-packages searxng granian

# ── Configs ──────────────────────────────────────────────────
COPY docker/searxng-settings.yml /etc/searxng/settings.yml
COPY docker/supervisord.conf /etc/supervisord/piargus.conf

# ── Ports ─────────────────────────────────────────────────────
EXPOSE 9222 8080

# ── Entry point ──────────────────────────────────────────────
CMD ["supervisord", "-c", "/etc/supervisord/piargus.conf"]
```

**Estimated image size:** ~700MB (Node ~200MB + Chromium ~200MB + Obscura ~70MB + SearXNG ~100MB + deps ~130MB)

### 4. `docker.ts` (replaces `smolvm.ts`)

New module managing the single Docker container via `docker` CLI. Same public API surface as `smolvm.ts`, different implementation.

**Container name:** `piargus`

**Key constants:**
```typescript
const CONTAINER_NAME = "piargus";
const SEARXNG_PORT = 8888;        // host port
const OBSCURA_PORT = 9222;        // host port
const SEARXNG_LOCAL_URL = `http://localhost:${SEARXNG_PORT}`;
```

**Public API (same names as smolvm.ts where possible):**

| Function | Docker command |
|----------|---------------|
| `isDockerInstalled()` | `docker --version` (check exit code) |
| `ensureContainer()` | `docker run -d --name piargus -p 127.0.0.1:9222:9222 -p 127.0.0.1:8888:8080 piargus` or `docker start piargus` if exists but stopped |
| `containerExec(cmd, opts)` | `docker exec [-e K=V]... piargus <cmd>` |
| `isSearXNGReady()` | `fetch('http://localhost:8888/healthz')` (HTTP, same as before) |
| `screenshot(url, output)` | Write Puppeteer script → `docker exec` node → base64 extract |
| `interact(url, actions)` | Write Puppeteer script → `docker exec` node → return HTML |
| `stopContainer()` | `docker stop piargus` |
| `getContainerStatus()` | `docker inspect --format='{{.State.Status}}' piargus` |

**Key differences from smolvm.ts:**
- No `smolvmExec()` → replaced with `dockerExec()` using same retry pattern
- No DB lock retry → Docker has no SQLite contention issue (remove that retry logic)
- No persistent exec session for Granian → supervisord manages Granian lifecycle
- No `_ensureSearchVmPromise` guard for Granian startup → still used for `ensureContainer()` dedup
- Chromium path: `process.env.CHROME_BIN || '/usr/bin/chromium'` (Debian path)
- NODE_PATH: `/usr/local/lib/node_modules` (global npm on Debian)
- Screenshot extraction: `docker exec piargus base64 /tmp/screenshot.png`
- Script writing: `docker exec piargus sh -c "cat > /tmp/script.js << 'SCRIPT' ... SCRIPT"`

**Screenshot/interact scripts:** Identical to current `SCREENSHOT_SCRIPT` and `INTERACT_SCRIPT` in `smolvm.ts` — just the `executablePath` default changes to `/usr/bin/chromium`.

## Modified Files

### 5. `obscura.ts` — Docker exec instead of local binary

**Before:**
```typescript
const bin = OBSCURA_PATH(); // local binary path
const { stdout, stderr } = await execFileAsync(bin, args, { ... });
```

**After:**
```typescript
await ensureContainer(); // lazy start
const { stdout, stderr } = await execFileAsync("docker", [
  "exec", "piargus", "obscura", ...args
], { ... });
```

- Remove `OBSCURA_PATH()` function
- `isInstalled()` → `isObscuraReady()` — checks if container is running and Obscura responds
- `execAsync()` wraps `docker exec piargus obscura <args>`
- All other functions (`fetchText`, `fetchHtml`, `fetchLinks`, `evalJs`) unchanged — they call `execAsync()`

### 6. `web-search-core.ts` — DDG scraping through Obscura

**`searchWeb()` changes:**
- Replace direct `fetch(url, ...)` to DuckDuckGo with Obscura container fetch
- Call `docker exec piargus obscura fetch "https://html.duckduckgo.com/html/?q=..." --dump html --quiet`
- Parse the returned HTML with the existing regex parser
- Provides anti-detection benefits (Obscura handles User-Agent, etc.)
- Import a helper from `obscura.ts` or `docker.ts` for the container fetch

### 7. `index.ts` — Update imports

- Remove all `./smolvm` imports
- Import from `./docker`: `ensureContainer`, `screenshot`, `interact`, `getContainerStatus`, `stopContainer`, `SEARXNG_LOCAL_URL`
- Update error messages: `"smolvm not installed"` → `"Docker not installed. Install: https://docs.docker.com/get-docker/"`
- Update `browser_vm_status` tool to report container status
- Update `session_shutdown` to call `stopContainer()`
- Update tool descriptions: remove "smolvm" → "Docker"

### 8. `tier-router.ts` — Update references

- `tierExplanation()`: `"smolvm+Chromium"` → `"Docker+Chromium"`

### 9. `types.ts` — Rename type

- `SmolvmState` → `ContainerState` (same values)

## How Each Tool Works (Post-Migration)

| Tool | Flow |
|------|------|
| `browser_navigate` | `docker exec piargus obscura fetch <url> --eval "JSON.stringify(...)` → returns title/url |
| `browser_fetch` | `docker exec piargus obscura fetch <url> --dump html/text/links --quiet` |
| `browser_scrape` | Parallel `docker exec piargus obscura fetch <url> --dump <mode>` calls |
| `browser_screenshot` | Write Puppeteer script → `docker exec -e PIARGUS_URL=... piargus node /tmp/screenshot.js` → base64 extract |
| `browser_action` (light) | `docker exec piargus obscura fetch <url> --eval <expr>` |
| `browser_action` (heavy) | Write Puppeteer script → `docker exec piargus node /tmp/interact.js` → return HTML |
| `web_search` (DDG) | `docker exec piargus obscura fetch "https://html.duckduckgo.com/html/?q=..." --dump html` → parse |
| `web_search` (SearXNG) | HTTP `POST http://localhost:8888/search` (JSON API) |
| `web_research` | DDG search → parallel `docker exec piargus obscura fetch <url> --dump text` → keyword extract |
| `browser_vm_status` | `docker inspect --format='{{.State.Status}}' piargus` + SearXNG healthz |

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| `docker exec` slower than local binary (~50ms overhead) | Container already running — acceptable for browser automation (ops take 1-30s) |
| Obscura Docker image missing `--stealth` flag | Document limitation; users needing stealth build from source with `--features stealth` |
| SearXNG startup time on first run | `ensureContainer()` polls `/healthz` with retries (same pattern as current smolvm) |
| Port conflicts (9222, 8888) | Use `127.0.0.1:` prefix; make ports configurable via env vars |
| Image build time (~700MB) | One-time cost; layers cached by Docker after first build |
| `supervisord` not in default `node:20-slim` | Install via `apt-get install supervisor` |
| Chromium path differs between Alpine and Debian | Use `/usr/bin/chromium` (Debian) instead of `/usr/bin/chromium-browser` |
